# 经验教训(实战沉淀,2026-09-29 ~ 10-01,一次商场国庆档 70 条短视频项目)

## 交付质量
| 现象 | 原因 | 解决 |
|---|---|---|
| 甲方:"AI 声音生硬、不欢快" | 免费 edge-tts 播报腔 | 改用剪映 SAMI(广告男声/促销男声…),整体语速 ×1.1~1.2 |
| 配音把"500、900"念成"五零零、九零零" | SAMI 对数字串逐位读 | 配音文本转中文读法;字幕仍用阿拉伯数字(`spoken_numbers`) |
| 字幕"XX奥莱国 / 庆节…" 劈词 | 按字数平均切,劈开了"国庆节" | 按词边界平衡切分 + 保护词表(`caption_words`);全文案池审计 |
| 甲方:"不要双节,要国庆节" | 用词 | 加入禁用词,生成器强制拦截 |
| 画面"有点抖" | zoompan 在 1080 分辨率下整数取整,缓推速度抖动 | 先 1.5~2 倍预放大再 zoompan,速度波动 0.76→0.43 |
| "掉帧" | 预览素材压成 30fps(原片 60fps) | 全部重转 60fps 预览,成片 60fps |
| 画面出现 9 月活动招牌 / 品牌自家折扣牌 | 素材拍摄于其他档期 | 素材索引风险标记,渲染时排除 |
| 结尾切到贴脸墙面废画面 | 素材开头是废帧 | 素材 `min_ss`(最早可用起点) |
| 同批 5 条镜头重合 30~58% | 并行渲染互相看不到已用素材 | 挑镜头阶段加文件锁,共享同批使用计数 → 平均 9% |
| 开头句重复 | 文案池小 + 随机抽 | 扩池 + "优先选本批用得最少的说法";70 条开头 44 种 |

## 工具链
- **剪映 skill(jianying-editor)**:草稿生成可用,但剪映 6.0+ 草稿加密、11.5 版本 UI 控件读不到 → **自动导出不可用**。真正有价值的是:SAMI 配音、云端音乐/音效、可精修草稿。
- 云端音乐 CSV 里的链接会过期 → `download_asset(id, force=True)` 按 ID 重新取。
- 剪映 SAMI 偶发断连 → 重试 + 缓存(同文案同音色只合成一次)。
- iPhone 素材多为 HEVC 10bit HLG HDR:不做色调映射会发灰;先缩到 1080 再 tonemap 快 3 倍。
- Windows 下 OpenCV 不能写中文路径:`cv2.imencode` + 写字节。

## 质检(自动质检自己也会出错)
- 整段 Whisper 转写会漏句、重复 → 按每句配音时长切片逐句转写。
- 给 Whisper 的 initial_prompt 如果和内容相同,会被当成"已说过"而跳过 → 用中性提示"以下是普通话的句子。"
- 不给提示会输出繁体 → zhconv 转简体。
- 中文数字换算:"四百五十团五百九百团一千"要拆成 450/500/900/1000,通用换算函数 + 负向前瞻。
- 自动"字错率"受识别噪声影响 10~20%,不作为硬指标;数字核对 + 人工抽帧才是准绳。

## 速度(RTX 4060 笔记本,16GB)
| 阶段 | 做法 | 效果 |
|---|---|---|
| 编码 | NVENC 显卡编码 | 合成 48s→21s |
| 运镜 | 镜头并行渲染 | 26s→8s |
| 转场 | 硬切段直接拼接,只在转场处 xfade | 减少整链滤镜 |
| 叠字幕 | 所有文字层按时间合成为少量整屏 PNG + 变化点转 yuva420p | 单条 62s→45s(60fps) |
| 并行 | 多条同时渲染 | CPU 满载后收益很小;瓶颈在 CPU 解码/滤镜 |
- 稳定后:60fps 单条约 45s,质检转写每条约 15~35s(可抽样)。

## 工作方式
- 手改生成出来的脚本会被下一次生成覆盖 → 永远改"源头"(文案池 / project.json / 生成器)。
- 改动渲染器前先备份;每次改完跑一条验证再批量。
- 先 5 条给甲方确认风格,再量产。

## 第二轮沉淀(体系化,2026-10)
| 现象 | 原因 | 解决 |
|---|---|---|
| 以为"批量并行更快",结果渲染随机失败(NVENC -22 / `Cannot allocate memory`) | 16GB 内存下多条同时做最终合成会内存不足;显卡编码会话数也有限 | 默认 `-j 1`;镜头渲染并发降到 4;每个镜头失败重试,最后一次退回 CPU 编码;失败的条自动串行重跑 |
| 以为 5 个风格就是"项目内容" | 风格写死在 `batch.py`,镜头类别也是某商场的名字 | 骨架数据化(`templates/skeletons`),镜头需求用通用角色名,项目用 `cat_alias` 映射;缺文案池/博主片段的风格自动跳过 |
| 手工标注的风险标记漏了很多 | 人工只标了"明显"的 | 入库打标:每段取首/中/尾三帧拼表,12 段一张,按固定字段打标(293 段后新增 64 段风险:汉堡节摊位、明星海报、品牌折扣价牌、儿童正脸…),可用空镜 165 → 121 |
| 新项目素材没打标就出片,画面里出现 SALE/折扣牌/儿童 | 没有门槛 | `batch.py` 默认拒绝使用未打标素材(`--allow-untagged` 才放行) |
| 口播字幕劈词 | 中文 whisper 的"词"只有 1~3 字 | 先 jieba 分词(加载项目词表),只在词边界换行 |
| 口播识别错字直接上屏 | small 模型口语识别不准 | 有文稿用 `--script`(difflib 对齐,保留时间);没有就用 medium 以上并人工看 |
| 口播原声里本身含禁用词("双节同庆") | 声音无法剪辑修改 | talk.py 转写后做合规检查并告警,由人决定剪掉哪段 |
| 配方卡里我手写的"哪些风格用了它"有 3 处写错 | 凭印象写 | `svf/cards.py check` 从骨架反推使用情况,双向核对,不一致就报错 |
| 模板 JSON 里 `frames/blur_px/scale` 等转场参数不生效 | 渲染器实际读的是 `render.py` 里的 `XF` | 已写进对应配方卡的"已知坑";以后以卡为准 |
| QC 把"八折"听成"发折/八者",报缺数字 | small 模型听错 | 仍是已知限制:数字核对只是提示,最终要人听 |

## 新领域验证(Pexels 免费咖啡店素材 20 段,2026-10)
- 不改代码,只写 project.json + 文案池 + 一个骨架,就出了 3 条 24 秒成片;入库 1.5 分钟、自动打标约 20 分钟、出 3 条约 3 分钟。
- **素材色彩范围(full range / yuvj420p)不一致会让合成中途报错**,ffmpeg 留下一个能播但被截断的 4~7 秒文件,解码检查发现不了 → 全链路统一 `scale=out_range=tv`,并在 run_batch 里比对成片时长与旁白总长。
- 质检读帧不足 16 张时整份报告崩掉 → 补黑帧。
- 价格"9.9"被读成"九块九",质检误报缺数字 → 加"X块Y"归一。
- 打标需要"内容"字段才能按角色选镜头 → 项目 `content_types` 定义内容类别,自动打标顺带分类,apply 写进素材索引的"内容"。
- 自动打标在这个领域效果明显好于商场素材(招牌/瓶身品牌、墙面文字都标出来了),但**漏了杯子和围裙上的 Gong Cha 标识**,抽查时人工补标。
- 素材里没有甜点镜头时,"甜点"那句会落到别的饮品镜头上(语义不完全对),补素材或改文案。
